## Casos de Testes de Integração (e2e)

Os testes de integração utilizam uma instância da API rodando em memória e realizam chamadas HTTP simulando clientes reais.

### Suite C: Autenticação e Segurança (Middlewares)

- **IT-01 (Não Autorizado):**
  - **Ação:** Fazer requisição `POST /sweepstakes` sem o cabeçalho `X-API-KEY`.
  - **Asserção:** A API deve retornar `401 Unauthorized`.
- **IT-02 (API Key Inválida):**
  - **Ação:** Fazer requisição com chave `X-API-KEY` incorreta ou inexistente no banco.
  - **Asserção:** A API deve retornar `401 Unauthorized`.

### Suite D: Fluxo de Criação e Ingresso no Bolão

- **IT-03 (Impedir Segundo Bolão Ativo via Endpoint):**
  - **Passo 1:** Criar um bolão com sucesso para o `Usuario A` via `POST /sweepstakes` (Retorno `201 Created`).
  - **Passo 2:** Enviar outro `POST /sweepstakes` com a mesma chave `X-API-KEY` do `Usuario A`.
  - **Asserção:** O segundo request deve retornar `400 Bad Request` com a mensagem indicando a restrição.
- **IT-04 (Associação de Participante por Código):**
  - **Passo 1:** Criar bolão com o `Usuario A` e extrair o `inviteCode` retornado.
  - **Passo 2:** Autenticar o `Usuario B` enviando sua chave `X-API-KEY` e fazer `POST /sweepstakes/join` com o código extraído.
  - **Asserção:** Retorno deve ser `200 OK` e o banco deve conter a associação do `Usuario B` a este bolão.

### Suite E: Lógica de Guesses e Prazo Limite

- **IT-05 (Bloquear Guess Após Deadline):**
  - **Ação:** Criar bolão com `guessesDeadline` definida para 10 minutos atrás. Tentar realizar um `POST /guesses` para este bolão com um guess de tabela final.
  - **Asserção:** A API deve retornar `400 Bad Request` informando que o prazo expirou.

### Suite F: Teste de Idempotência (`Idempotency-Key`)

- **IT-06 (Evitar Duplicação de Guess):**
  - **Passo 1:** Enviar `POST /guesses` com o cabeçalho `Idempotency-Key: 123e4567-e89b-12d3-a456-426614174000` contendo a `finalTable`.
  - **Asserção 1:** API retorna `201 Created` e o guess é gravado no banco de dados.
  - **Passo 2:** Enviar **exatamente o mesmo payload e cabeçalhos** (mesma chave `X-API-KEY` e mesma `Idempotency-Key`).
  - **Asserção 2:** API retorna `200 OK` ou `201 Created` rapidamente, mas **sem fazer um novo insert** no banco de dados (o contador de guesses do participante no banco deve continuar igual a 1).
